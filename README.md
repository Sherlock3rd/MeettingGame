# MeettingGame — 灰烬之子 · 会所议事夜

同一套帮派会议玩法下的四种体验表达：谁先领头、一诺换票、把事安排妥、各领其命。

## 设计讨论更新（2026-11-14）

最新结构为三步：设计目的（渐进身份体验 / 常驻选择体验）→ 一日scope与会议落点 → 实现体验比较。第二步简化为序章至第五章的六张纵向章节卡，每章列剧情概述、关键事件顺序和关键系统；已有会议单独标记。保留7个可见候选落点及一个可移动pin，默认序章到第一章。调整工具与来源说明默认收起，原25条事件依据保留在数据和折叠资料。支持拖放、点击、下拉与键盘，锚定及备注在当前浏览器保留，并同步显示于第三步。不会写飞书或修改原事件，不提供多人实时同步。

数据源为 `meeting-timeline.json`（工作台），生成 `playtest/meeting-timeline-data.js`；交互与样式分别为 `scope-timeline.js/css`。第四/第五章仅为用户指定的填充范围，两份台本未给事件。L09保留会议黑盒；常驻政令在原表列为7日，未标为一日已完成。

完整双 CP 分析保留为第三步之后的展开资料，包含阶段图、参考证据、变量、范围与优缺点。一次真实任务/奖励分岔为 CPA 候选，当前 demo 未实现。本次发布包含上述设计讨论、纵向剧情轴与 CPA / CPB 命名更新。

`playtest/progression-notes.js` 由工作台主文档 `docs/reference-briefings/gang-council-voting-minigames/brief.md` 经同目录 `build-progression-notes.py` 生成；不改变投票或任务逻辑。

## 基础设计支点

游戏以假单机方式呈现会议，成员态度、票型和回应可由系统编排，玩家选择可以被引导。选择主要改变当场参与、回应与分工感受，对后续实际体验影响有限，最终统一收束到相同主线。四版用于比较带动感、被回应感、统筹感与主动承担感，不以独立玩法、长期代价或主线分支作为必要目标。
